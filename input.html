1. Two Pointers

Two index variables moving toward or away from each other — eliminates inner loop

Problems Solved

✅ Union of Two Sorted Arrays  ·  ✅ Intersection of Two Sorted Arrays  ·  ✅ 3 Sum  ·  ✅ 4 Sum

🚨 Signal Words — Use Two Pointers when you see:
  • "Two sorted arrays" / "Find pair with given sum"
  • "Find triplet/quadruplet summing to target"
  • "Remove duplicates in sorted array"
  • "Palindrome check" / "Container with most water"

The 3 Variants

Variant 1 — Opposite Ends (Most Common)

i starts left, j starts right. Move based on condition (sum too big/small).

i=0 ──────────────►
◄────────────── j=n-1

Used in: 2Sum, 3Sum, 4Sum

Variant 2 — Same Direction (Slow-Fast)

j moves faster than i. Used for window-like problems on arrays.

slow=0 ──►
fast=0 ──────────────►

Used in: Remove duplicates,
         Linked List cycle

Variant 3 — Two Arrays

One pointer per array. Always advance the pointer with smaller value.

i moves on array A ──►
j moves on array B ──►

Used in: Union, Intersection,
         Merge Sorted Arrays

k-Sum Pattern Ladder

ProblemLoopsTechniqueTime
2 Sum (sorted)0 outerTwo PointersO(N)
3 Sum1 outer (fix i)Two Pointers insideO(N²)
4 Sum2 outer (fix i,j)Two Pointers insideO(N³)
k Sumk-2 outerTwo Pointers insideO(N^(k-1))
💡 Rule of Thumb

If you have a sorted array and need to find elements satisfying a condition, Two Pointers eliminates the inner loop: Brute O(N²) → Optimal O(N).

Duplicate Skipping (3Sum / 4Sum)

sort(arr);
for (int i = 0; i < n-2; i++) {
    if (i > 0 && arr[i] == arr[i-1]) continue;  // skip dup for i

    int j = i+1, k = n-1;
    while (j < k) {
        int sum = arr[i] + arr[j] + arr[k];
        if (sum == 0) {
            result.push_back({arr[i], arr[j], arr[k]});
            while (j < k && arr[j] == arr[j+1]) j++;  // skip dup j
            while (j < k && arr[k] == arr[k-1]) k--;  // skip dup k
            j++; k--;
        }
        else if (sum < 0) j++;
        else              k--;
    }
}

2. Sliding Window

A window [left, right] that expands and shrinks — avoids recomputing full subarray

Problems Solved

✅ Longest Subarray with Sum K (positives only)

🚨 Signal Words
  • "Subarray/substring of size k"
  • "Longest/shortest subarray with property"
  • "Maximum sum subarray of fixed size"
  • "All positives + sum/condition"

The Golden Rule — When does Sliding Window work?

✅ Positives Only → Use Sliding Window

add right  → sum INCREASES
remove left → sum DECREASES
Direction is predictable!

if sum > k → shrink from left
if sum < k → expand right

❌ With Negatives → Window Breaks

add right  → sum could go UP or DOWN
remove left → no guarantee

Cannot predict direction
→ Use Prefix Sum + HashMap instead

Variable Window Template

int left = 0, right = 0, sum = 0, maxLen = 0;

while (right < n) {
    sum += arr[right];          // EXPAND window

    while (sum > k) {           // SHRINK when violated
        sum -= arr[left];
        left++;
    }

    if (sum == k)
        maxLen = max(maxLen, right - left + 1);

    right++;
}
return maxLen;
TypeApproachExample
Fixed size windowAdd right, remove left simultaneouslyMax sum of k elements
Variable size windowExpand right greedily, shrink left when violatedLongest subarray sum = k

3. Prefix Sum + HashMap

Precompute cumulative sum/XOR — answer subarray queries in O(1)

Problems Solved

✅ Count Subarrays with Sum K  ·  ✅ Longest Subarray with Sum K (negatives)  ·  ✅ Largest Subarray Sum 0  ·  ✅ Count Subarrays XOR K

🚨 Signal Words
  • "Subarray sum/XOR equals k" (with negatives or zeros)
  • "Count/find subarrays with property"
  • "Can't use sliding window (negatives present)"
  • "Longest subarray with given sum"

The Core Identity

sum(i to j) = prefixSum[j] - prefixSum[i-1]

So: prefixSum[j] - prefixSum[i-1] = k
→   prefixSum[i-1] = prefixSum[j] - k

For every j: "How many previous i's have prefixSum = current - k?"
→ HashMap answers this in O(1)!

The 3 Critical Variants

VariantGoalMap StoresMap InitMap Update
COUNT subarrays sum = k count += map[sum - k] prefixSum → frequency {0 : 1} map[sum]++  (always)
LONGEST subarray sum = k maxLen = max(maxLen, i - map[sum-k]) prefixSum → first index {0 : -1} map[sum] = i  (only if absent)
COUNT subarrays XOR = k count += map[xor ^ k] prefixXOR → frequency {0 : 1} map[xor]++  (always)
💡 Why {0:-1} vs {0:1}?

Count variant {0:1} — empty prefix appeared once → correctly counts subarrays starting at index 0.

Longest variant {0:-1} — empty prefix is "at index -1" → length = i - (-1) = i+1 = correct length starting from index 0.

Code Templates

// VARIANT 1: Count subarrays with sum = k
unordered_map<int,int> mp;
mp[0] = 1;
int sum = 0, count = 0;
for (int x : arr) {
    sum += x;
    count += mp.count(sum - k) ? mp[sum - k] : 0;
    mp[sum]++;              // always update
}

// VARIANT 2: Longest subarray with sum = k
unordered_map<int,int> mp;
mp[0] = -1;
int sum = 0, maxLen = 0;
for (int i = 0; i < n; i++) {
    sum += arr[i];
    if (mp.count(sum - k)) maxLen = max(maxLen, i - mp[sum - k]);
    if (!mp.count(sum)) mp[sum] = i;  // only first occurrence!
}

// VARIANT 3: Count subarrays with XOR = k
unordered_map<int,int> mp;
mp[0] = 1;
int xr = 0, count = 0;
for (int x : arr) {
    xr ^= x;
    count += mp.count(xr ^ k) ? mp[xr ^ k] : 0;
    mp[xr]++;
}

4. HashSet / HashMap for Lookup

O(1) existence checks instead of O(N) linear search

Problems Solved

✅ Longest Consecutive Sequence  ·  ✅ Two Sum (unsorted)  ·  ✅ Contains Duplicate

🚨 Signal Words
  • "Does this element exist in array?" asked repeatedly
  • "Find duplicates" / "Consecutive numbers"
  • "Two sum (unsorted)" / "Group elements by property"

The Core Trade-off

// Before: O(N) per existence check
for (int j = 0; j < n; j++)
    if (arr[j] == target) return true;   // O(N) every time!

// After: O(1) per existence check
unordered_set<int> st(arr.begin(), arr.end());
if (st.count(target)) ...               // O(1) every time!

Trading O(N) space for O(N) time improvement per query.

Longest Consecutive Sequence — The Key Trick

// Only start counting from the ACTUAL start of a sequence
// x is a start if (x-1) does NOT exist in the set

for (int x : arr) {
    if (!st.count(x - 1)) {      // x is start of sequence
        int curr = x, len = 1;
        while (st.count(curr + 1)) { curr++; len++; }
        maxLen = max(maxLen, len);
    }
    // if x-1 exists → x is NOT a start → SKIP (avoid recount)
}
// Each element visited at most twice → O(N) total!

HashSet — Existence Only

unordered_set<int> st;
st.insert(5);
st.count(5);   // → 1
st.find(5);    // → iterator

Used when: "Does X exist?"

HashMap — Existence + Value

unordered_map<int,int> mp;
mp[5] = 3;
mp.count(5);   // → 1
mp[5];         // → 3

Used when: "Does X exist AND what's
its index/frequency?"

5. Sorting as Preprocessing

Sort once, unlock Two Pointers / Binary Search / easy duplicate handling

Problems Solved

✅ 3 Sum  ·  ✅ 4 Sum  ·  ✅ Union/Intersection  ·  ✅ Next Permutation (sort suffix)

🚨 Signal Words
  • "Find pairs/triplets with given sum"
  • "Remove duplicates from result"
  • "Skip duplicate elements in input"
  • "Binary search needed on array"
💡 Rule of Thumb

If the order doesn't matter in the answer but sorted order helps find it → sort first. O(N log N) preprocessing is worth it when it unlocks O(N) or O(N²) instead of O(N²) or O(N³).

6. Boyer-Moore Voting Algorithm

Find majority elements in O(N) time and O(1) space via cancellation

Problems Solved

✅ Majority Element I (>N/2)  ·  ✅ Majority Element II (>N/3)

🚨 Signal Words
  • "Element appearing more than N/k times"
  • "Majority element" + "O(1) space required"

The Cancellation Insight

If majority element appears > N/2 times,
even if every other element "votes against" it,
it still survives cancellation!

Think of it as an election:
- Majority has more votes than ALL others combined
- Cancel one majority vote with one minority vote
- Majority still wins!
ThresholdMax CandidatesCounters Needed
> N/211 (cand1, cnt1)
> N/322 (cand1+cand2, cnt1+cnt2)
> N/kk-1k-1

Two-Phase Template

// PHASE 1: Find candidates
int cand1, cand2, cnt1 = 0, cnt2 = 0;
for (int x : arr) {
    if (x == cand1)       cnt1++;
    else if (x == cand2)  cnt2++;
    else if (cnt1 == 0) { cand1 = x; cnt1 = 1; }
    else if (cnt2 == 0) { cand2 = x; cnt2 = 1; }
    else { cnt1--; cnt2--; }     // cancellation!
}

// PHASE 2: Verify (candidates are NOT guaranteed!)
cnt1 = cnt2 = 0;
for (int x : arr) {
    if (x == cand1) cnt1++;
    else if (x == cand2) cnt2++;
}
if (cnt1 > n/3) result.push_back(cand1);
if (cnt2 > n/3) result.push_back(cand2);
⚠️ Why Phase 2 is Mandatory

Phase 1 gives you CANDIDATES, not guarantees. arr=[1,2,3] has no majority, but phase 1 will still return some survivor. Always verify by counting.

7. Matrix Manipulation Patterns

Set Zeroes · Rotate · Spiral — each needs a different insight

Problems Solved

✅ Set Matrix Zeroes  ·  ✅ Rotate Matrix 90°  ·  ✅ Print Spiral Matrix

Set Matrix Zeroes

Signal: "Modify matrix based on existing values"

Rule: NEVER modify while reading → two-pass

Pass 1: Record rows[] and cols[]
        that need zeroing
Pass 2: Apply zeroes

O(1) space trick: use first
row and first col as markers

Rotate Matrix 90°

Signal: "Rotate N×N matrix in-place"

Mathematical identity to memorize:

Clockwise 90°:
  Step 1: Transpose
  Step 2: Reverse each row

Anti-clockwise 90°:
  Step 1: Transpose
  Step 2: Reverse each column

Spiral Matrix

Signal: "Traverse layer by layer / onion peeling"

4 boundaries:
  top, bottom, left, right

Each pass: go in one direction,
shrink that boundary inward.

Guard: check top<=bottom and
left<=right before left/up pass

Rotate Matrix — Code

void rotate(vector<vector<int>>& matrix) {
    int n = matrix.size();

    // Step 1: Transpose (j starts from i+1 to avoid double-swap!)
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            swap(matrix[i][j], matrix[j][i]);

    // Step 2: Reverse each row
    for (int i = 0; i < n; i++)
        reverse(matrix[i].begin(), matrix[i].end());
}

8. Suffix / Prefix Traversal

Carry running information about the suffix/prefix to avoid repeated scans

Problems Solved

✅ Leaders in Array (suffix max)  ·  ✅ Next Permutation (find dip from right)  ·  ✅ Check Sorted & Rotated (count drops)

🚨 Signal Words
  • "Greater than all elements to the RIGHT" → traverse right to left
  • "Find first decrease/increase from the right"
  • "Max/Min of everything on one side"

Suffix Max (Right to Left)

int maxRight = INT_MIN;
for (int i = n-1; i >= 0; i--) {
    if (arr[i] >= maxRight) {
        result.push_back(arr[i]); // leader!
        maxRight = arr[i];
    }
}
// Used in: Leaders in Array

Count Drop Points (Circular)

int drops = 0;
for (int i = 0; i < n; i++) {
    if (nums[i] > nums[(i+1) % n])
        drops++;
}
return drops <= 1;
// Used in: Check Sorted & Rotated

Next Permutation — 3-Step Algorithm

Step 1: Find "breakpoint" (dip) from right
  → First i where arr[i] < arr[i+1]

Step 2: Find just-greater element from right
  → Smallest element in suffix that is > arr[i]
  → Swap it with arr[i]

Step 3: Reverse the suffix after index i
  → Suffix was descending → reversing makes it ascending (smallest)

If no breakpoint found → already last permutation → reverse all

9. Mathematical / Formula-Based

Leverage mathematical properties to avoid brute computation

Problems Solved

✅ Pascal's Triangle (nCr)  ·  ✅ Rotate Matrix (position formula)  ·  ✅ Majority Element

Pascal's Triangle — 3 Question Types

Question TypeApproachTime
Single element at (r, c)nCr formula iteratively: res = res*(n-i)/(i+1)O(C)
Entire row rBuild each element from previous: elem[j] = elem[j-1]*(n-j)/jO(N)
Generate n rowsBuild each row from previous rowO(N²)
// Generate all n rows
vector<vector<int>> pascalTriangle(int n) {
    vector<vector<int>> result;
    for (int i = 1; i <= n; i++) {
        vector<int> row(i, 1);          // all 1s first
        for (int j = 1; j < i-1; j++)  // fill middle
            row[j] = result[i-2][j-1] + result[i-2][j];
        result.push_back(row);
    }
    return result;
}

10. Hashing — Deep Dive into Complexity

Every data structure, every operation, every pitfall

How Hashing Works Internally

HashMap/HashSet = Array of BUCKETS

Key → Hash Function → Bucket Index → store value there

key = "apple"
hashCode("apple") % 16 = 3  → store in bucket[3]

bucket[0] → empty
bucket[1] → empty
bucket[2] → empty
bucket[3] → ("apple", 5)   ← stored here
bucket[4] → empty ...

Collision & Worst Case

COLLISION: Two keys map to same bucket

key1 = "apple" → bucket[3]
key2 = "mango" → bucket[3]  ← SAME BUCKET!

Resolution: linked list in bucket
bucket[3] → ("apple",5) → ("mango",3) → null

NO collision  → O(1) lookup  (direct bucket access)
WITH collision → O(N) lookup  (traverse linked list)

Average case: collisions are rare → O(1)
Worst case:   all keys collide   → O(N)

The Upgrade Ladder

Every problem follows this improvement path:

O(N³) → O(N²) → O(N log N) → O(N) → O(1) space

At each step ask:
  "What am I RECOMPUTING that I could PRECOMPUTE?"
  "What am I SEARCHING that I could STORE?"

Recomputing inner loop sum → Carry running sum     (N³ → N²)
Searching for element      → HashSet               (N² → N)
Need ordering + no hash risk → map instead of unordered_map
